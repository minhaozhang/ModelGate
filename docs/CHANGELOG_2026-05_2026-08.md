# 第一部分：性能优化与 Bug 修复（详述）

## 1. 性能优化

### 1.1 仪表盘统计查询脱离 1.2GB 视图（08-03 `33eecd9`）
- **现象**：admin/用户仪表盘 day/week/month 查询走 `request_logs_all` 视图（`request_logs` + `request_logs_history` 的 UNION，全量 1.2GB 扫描），秒级耗时；`get_api_key_stats` 甚至无时间边界全表扫。
- **修复**：有界时间窗查询改打 live 表 `request_logs`（`created_at` 有索引）；year 粒度走日聚合表；`get_api_key_stats` 加 30 天截断。日志查看器和报表保留用视图（ genuinely 需要跨表历史）。
- **附带**：连接池从硬编码 20/30 降到 `DB_POOL_SIZE=5`/`DB_MAX_OVERFLOW=5`（env 可调），防小内存主机连接耗尽。
- **效果**：day/week/month 查询从多秒降到 ~50ms。

### 1.2 /stats 总量改走日聚合 + 当日缓存（08-04 `5b8475f`）
- **现象**：`/stats` 顶部总量 4 个 count/sum 全打 1.2GB 视图，400-500ms。
- **修复**：历史部分 `SUM(provider_daily_stats)`（~700 行、索引）；当日复用 `get_cached_today_stats()` 进程内缓存。边界正确性：`aggregate_yesterday_stats()` 每日只写昨天，今日不会双计。
- **效果**：实测 80ms 冷 → 18ms 热。

### 1.3 周总量走日聚合 + 修聚合桶 KeyError（08-17 `d6b5043`）
- 周总量（`/stats/period`、`/stats/aggregate`）从整周 ORM 全载改为日聚合表 + 窗口头部的亚日部分用有界 raw 扫描（聚合从窗口内第一个午夜开始，头天不足整日不重复计）。趋势/图表周视图仍走 raw（4 小时桶无法用日聚合表示）。
- **顺带修 bug**：provider 同时出现在日聚合和今日 raw 尾部时 `keys` 桶缺失导致 KeyError。

### 1.4 删除冗余/零使用索引（08-16 `5c0ac05`）
- 依据 pg_stat_user_indexes 扫描计数清理：`uq_request_logs_history_id`（与主键重复，ON CONFLICT 仍走 pkey）、`idx_request_contents_log_id`（与唯一约束重复）、4 个零扫描索引（history.provider_id、audit_logs 三项、task_logs.task、analysis_records 两项）、2 个与 `ix_*_created_at` 重复的死索引。模型定义同步删除防 `create_all` 重建，启动时 `DROP INDEX IF EXISTS`。

### 1.5 意图分类器基于 2.5 万条生产日志重写（08-05 `255ece6` + `70cb616`）
- **问题**：旧分类器大量误判——writing 误报泛滥（UI 标签词如「改写/报告」被当成写作意图）、agent 协议噪音（system-reminder、工具回显）干扰、全部偏向 coding。
- **修复**：只扫用户消息；过滤 agent 协议噪音；短续接短语继承同请求先前意图；收紧写作关键词；仅无歧义 testing 标记允许强关键词覆盖；camelCase/snake_case/反引号代码标识检测（chat→coding）；文件路径/堆栈上下文否定 writing/design。
- **后续 bug**：camelCase 检测拿了 lower() 后的文本（大写被抹掉正则失效），改用原始大小写；「页面」关键词重复登记破坏 design/coding 平局裁决，去重。
- **效果**：全量 25k 日志验证 coding +16%、writing -97%（几乎全是误报）、chat +170%（框架噪音被正确过滤）。

### 1.6 请求日志列表紧凑表格化（08-05 `965b093`）
- 8 列卡片网格改为粘性表头真表格，行高 ~120px → ~38px，同屏行数 ×3；错误行红显、缓存命中角标、暗色模式保持。

## 2. 后端正确性与稳定性修复

### 2.1 并发排队代替秒拒 429（08-21 `be18dbc`）— 本季最重要的可用性修复
- **现象**：opencode agent 会话「试几次就停」。推理模型流式请求占并发槽可达数分钟，旧信号量 acquire 超时 1s，并发请求几乎必然立刻 429；opencode/ai-sdk 遵守 retry-after 重试 6 次的预算在槽位释放前耗尽，agent 放弃。
- **修复**：acquire 超时提到 10s（env `MODELGATE_SEMAPHORE_ACQUIRE_TIMEOUT` 可覆盖）；等待队列超过 limit×2 时立即 429（限制队列深度，防高负载雪崩），429 统一带 5s retry-after 头。
- **验证**：limit=1 信号量下 4 路并发流全部 200，排队 0/3/7/11s，零 429。

### 2.2 模型可见性与供应商瞬时状态解耦（08-21 `d37d380`）
- **现象**：glm-5.3 的供应商被熔断禁用后，模型从 `/v1/models` 和 opencode merge 配置里消失——用户明明有权限，配置却被覆盖丢模型。
- **根因**：可见性查询 JOIN `Provider.is_active` 过滤，把限流器的临时禁用当成了权限过滤。
- **修复**：可见性只跟权限（grants + 绑定 `ProviderModel.is_active`）走；供应商可用性由请求路由层处理。绑定（显式管理动作）禁用仍隐藏模型。
- **验证**：E2E——禁用供应商模型保留；禁用绑定模型消失；还原后恢复。

### 2.3 GLM 健康检查对推理模型误报（08-20 `4861a28`）
- **现象**：每日 05:30 健康检查对推理模型报「上游空响应」误判。
- **根因**：探测请求 `max_tokens=8`，推理模型把预算全花在 reasoning 上（`finish_reason=length`、`message.content` 为空），检查逻辑误读为上游故障。
- **修复**：`max_tokens` 提到 256，并把 `reasoning_content` 也视为上游存活的证据。

### 2.4 统计周期总量的分拆列修正（08-18 `8f984e2`）
- **现象**：年等聚合周期的 rate_limited/errors/timeouts 显示为 0；prompt/completion 分拆在聚合周期同样为零。
- **根因**：日聚合表没有这些分拆列，旧代码用 live 表覆盖块补救但只覆盖部分周期，且 errors 混计了非 error 状态。
- **修复**：四张日聚合表新增 prompt/completion/timeouts 列，errors 只计 `status=error`；一次性回填（system_settings 标志防重跑）；聚合周期直接 SUM 新列；趋势/图表接通每日 timeouts；前端紧凑 token 格式加 B 档。

### 2.5 NULL 字节清洗（06-19 `ed39c83`）
- **现象**：请求内容里带 `\x00` 时 asyncpg 抛 `UntranslatableCharacterError`，写日志失败。
- **修复**：所有 DB 写入路径统一清洗 NULL 字节。

### 2.6 nginx 流式提前截断（06-20 `bee642d`）
- **现象**：长流式响应（推理模型数分钟）中途断掉。
- **根因**：nginx 默认代理超时 60s < httpx 客户端 600s。
- **修复**：nginx `proxy_read_timeout` 提到 600s 对齐。

## 3. 前端 UI Bug 修复

### 3.1 两个同根因的 Tailwind 编译坑
构建流程不会产出任意值类（arbitrary value classes），写进模板的类名静默失效：
- `53fb844`（07-17）：`max-h-[calc(100dvh-4rem)]` 未编译，60+ key 时保存按钮掉出视口——改用既有的 `.admin-modal-card`。
- `bf898e5`（07-09）：`bg-black/40` 未编译，弹窗遮罩完全不遮罩——改内联 `rgba(0,0,0,0.5)`。

### 3.2 暗色主题系列
- `8a3dde1`（08-15）：**白闪**——主题 class 在 body 深处 ~1194 行才应用，浏览器先画白屏。改为 head 内早期 boot 脚本读 cookie 设 html 背景 + MutationObserver 在 body 创建瞬间挂 class，首帧前生效；移动端暗色从「有 CSS 无脚本」变为可用。
- `1f0b108`（08-15）：boot 脚本路径守卫 `indexOf('/admin') === 0` 在生产 `/modelgate/admin/...` 挂载下永不匹配，白闪修复在生产无效——改为匹配 pathname 中任意位置的 /admin 段。
- `d0cb5fc`（08-14）：暗色下行 hover 近白底配近白字——`hover:bg-gray-50/100` 编译出自己的选择器，静态 `!important` 覆盖匹配不到；全局规则在暗色/黑金下重映射为 slate/gold 色调。
- `aeeb205`（08-20）：供应商横幅琥珀色类无暗色覆盖。

### 3.3 tooltip 三连修
- `1692aea`（08-13）：warn/help tooltip 单行 nowrap 挤成细条——横向展开。
- `3abdeef`（08-19）：长文本 + 图标在行中部时 tooltip 溢出右缘出横向滚动条——委托 mouseover 处理器，按最近裁剪祖先（弹窗滚动区）或视口钳制，收缩 max-width 并左移。
- `35165fd`（08-20）：弹窗右缘触发器 tooltip 越界——允许负 left 偏移、向上开被裁剪时翻转到下方。

### 3.4 opencode setup 脚本解析
- `5a4ef5d`（08-21）：行内注释剥离正则 `(?<!:)//` 吃掉 `file:///D:/...`（第二个 `//` 前是 `/` 非 `:`），字符串截断、JSON 解析失败，用户被推向「丢弃现有配置」的破坏性分支——lookbehind 扩为 `(?<![:\"'/\w])`；bash 版加整行剥离 fallback。
